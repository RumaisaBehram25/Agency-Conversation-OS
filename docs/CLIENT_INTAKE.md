# Client intake — credentials & setup

## Credentials to collect from the client (secrets & IDs)

These are the values you paste into Attora (org settings / dashboard) or use in ManyChat.

### Required for live ManyChat → Attora

| Credential | Example shape | Where it lives |
|------------|---------------|----------------|
| **ManyChat API key** | string | ManyChat → Settings / API |
| **ManyChat page ID** | string | Page / bot settings |
| **ManyChat account ID** | string | Account-level identifier |

### Optional — Meta (ads, CAPI events, ad spend in analytics)

| Credential | Example shape | Where it lives |
|------------|---------------|----------------|
| **Meta Pixel ID** | numeric string | Events Manager → Pixel |
| **Meta CAPI access token** | long string (secret) | System user or Events Manager–generated token with `ads_management` / CAPI as needed |
| **Meta ad account ID** | `act_1234567890` | Ads Manager |
| **Meta Page ID** | numeric string | Page settings |
| **Meta Business Manager ID** | numeric string | Business Settings |

Treat **API keys and CAPI tokens** like passwords: share over a vault or encrypted channel, not plain email if you can avoid it.

### Generated by you (not “from client,” but client must use it)

| Credential | Who creates it | Used for |
|------------|------------------|----------|
| **Attora API key** (`atk_…`) | Auto-generated when you **create the org** in Attora | ManyChat **External Request** header `X-Attora-Key` — authenticates webhooks to your backend |

Give the client this key only if **they** configure ManyChat; otherwise you keep it and configure flows yourself.

### Dashboard login (identity, not third-party API)

| Credential | Notes |
|------------|--------|
| **Owner email + password** | Client registers on your Attora URL, or you create and share login securely — **not** the same as ManyChat/Meta keys |

---

## Non-credential items (content, not secrets)

- Product names, prices, checkout URLs  
- Brand voice, compliance text, objection replies, greetings  
- Operational: who approves ManyChat flow changes  

---

## What you never ask the client for (your infrastructure)

| Item | Who holds it |
|------|----------------|
| **Anthropic API key** (`sk-ant-…`) | Your server `.env` unless you contract “BYO Anthropic” |
| **Postgres / Redis / JWT / encryption secrets** | Your deployment only |

---

## One-line “creds only” ask (copy-paste)

> Please send securely: **ManyChat API key**, **page ID**, **account ID**. If you want Meta reporting and conversion events: **Pixel ID**, **CAPI access token**, **ad account ID** (`act_…`). We’ll give you our **Attora webhook URL** and (if you configure ManyChat) the **Attora API key** for the webhook header.
